## 5. 直した本物の欠陥のうち、特に重いもの

### 5-1. コードがページの境で切れとった（局長の指摘が起点）

day13 p12 で `taskRouter` の宣言が `.input(` の途中で切れ、続きが次ページに落ちていました。
**写経が前提の教材で、読者は打ちながら紙をめくることになります。**

`book.css` の `pre` に `break-inside: avoid` を入れ、塊ごと次ページへ送るようにしました。
1ページに収まらん長さの塊は CSS の規定どおり分割されるので、コードが消えることはありません。
境に1〜2行だけ残る形も `orphans / widows: 4` で防いでいます。

代償はページ数です。36冊の合計で 2,600 → 2,879ページ（+279 / +10.7%）。
塊を丸ごと次ページへ送る以上ページは増えるので、増えたこと自体は想定どおりです。
増えた分と引き換えに何が良くなったかは紙面検査で測っており、
**36冊すべてで紙面の指摘が 0 件**、前より崩れた冊は 1 冊もありません。

**二度と戻らんように機械で見張る仕組みも足しました。**版面の下端に厚みのある濃い地色があり、
次ページの上端も同じなら「コードブロックがページの境で切れている」と報告します。
表の罫線1本を拾わんよう厚みの条件つきです。

### 5-2. 表の中のファイルパスが隣の列へ突き抜けとった

`src/server/api/routers/project.ts` が折り返さず、「成功状態」列の文字に重なって
紙の右端を最大24mm越えていました。セルの中の `code` に `word-break` を当てて解消。

### 5-3. 5列の表で5列目が消えとった

`book.css` の列幅比率が `th:nth-child(1..4)` に当たっており、5列の表では1〜4列目が
幅を100%使い切って5列目に何も残りませんでした。1文字ずつ縦に潰れていました。
比率を「ちょうど4列の表」に限定し、5列は等幅にしました。

**既存の `check_pdf_book.py` は、この状態の day26 を「✅ 商品として出せる状態です」と
言っていました。**紙面の崩れを見る検査が1本も無かったためです。

### 5-4. 読者の Day 02 の画面に、壊れた日本語が一番大きく出とった

```
おはよう、Taroさん。今日は ダッシュボードに自分だけのメッセージを追加する を前に進める日だ。
```

`todayFocus` が動詞句なので「〜する を前に進める」となり、日本語として壊れています。
「今日は〜する日だ。」に直しました（day02 に4箇所、day08 に1箇所）。

### 5-5. Day 04 の画像2枚が、本文と真っ向から矛盾しとった

`day04-prep-panel.png` は「**まだ本番公開はしません**」「今日はやらない: **本番公開**」、
`day04-sample-url.png` は「正式な公開手順は **Day 30 で実施する**」と書いています。
いっぽう今の day04 はタイトルが「ネットに公開」で、本文は
「Vercel につなぎ、**実際の URL で公開します**」です。

**画像が「今日はやらない」と言うとることを、本文は「今日やる」と言うています。**
Day 04 が「友達に送る準備」やった古い版の残骸で、教材の書き直しに追従していません。

ほかに3点あります。キャプションが言う準備物3つ（push / `npm run build` / 環境変数）と
画像のカード3枚（URL / 完成画面 / 本番公開）が1つも一致していません。Day 04 の時点で
存在せんサイドバーと「User Admin 管理者」が映っています。サイドバーが切れて本体に重なり、
下半分の約55%が白場になっています。

**買い手が4日目に当たる矛盾**なので、置き場所としては最悪の部類です。
削除と、公開URLで開いた実画面2枚の撮影を、撮影担当へ回しました。
`check_visualization.py` が「スクショ位置3箇所以上」を要求するため、
削除だけ先に入れることはできません。同じ変更でまとめる必要があります。

### 5-6. 理解チェックの書式が21日と9日で割れとった

day22〜30 は答えを `> **答え**:` の引用で書いており、**textlint が引用の中を読まないため
27問の答えが文章検査を素通りしていました**。書式を多数派へそろえた途端、
助詞の重なりなどが4件出てきました。形を見る検査 `check_quiz.py` を新設しています。

## 6. 覆した判断

担当が「教材の欠陥」と報告してきたものを、教材を自分で読んで**1件覆しました**。

**day11 の型エラー5件**は、本文がこう先に断っています。

> この時点ではエディタに `getById` が無いという型エラーが出ます。**写し間違いではありません。**
> 実際に数えると5件出ます。…**Day 11 を終えた時点で `npm run build` は通りません。今日は失敗して正常です。**

確認ポイントにも「型エラーが5件出ても、そのまま次へ進む」と入っています。
読者の手元で起きることと道具の観測は一致しており、隠れた欠陥ではなく**先に断ってある赤**です。

`build_day_snapshots.py` に `EXPECTED_RED` を置き、想定内として扱うようにしました。
あわせて逆向きの検査を入れています。**教材が「落ちる」と断っている日が通ってしまったら失敗**に
します（断りのほうが古いということなので、直す先は本文になります）。
断りの無い日をそこへ足して赤を隠せんよう、本文に断りがあることを確かめる検査も入れました。

## 9. リリース後へ回したもの

`doc/post-release-backlog.md` に9項目を置いてある。それぞれに「なぜ今やらんでええか」を
1行付けてある。要約は次のとおり。

| 項目 | 今やらん理由 |
|---|---|
| コードの実務水準レビュー（指摘13件） | 売っているのは教材の文章と画面。アプリは題材で単体では売っていない |
| pre-commit の O(n²) | 実測2分台。遅いだけで成果物は変わらない |
| #386 以外の PR / Issue（6件） | どれも出荷物に載らない |
| branch protection の登録 | 上記のとおり局長の作業。運用は現状1人 |
| main の npm audit 赤 | 5件すべて開発依存で配布物に入らない |
| 1日の分量のばらつき | 分割の是非は「そこで休んで壊れんか」の実測が要る（局長判断で現状維持） |
| 1冊綴じPDF・markdown 同梱・LP | 局長判断で今回の範囲外 |

コードレビューの13件（HIGH 5 / MEDIUM 4 / LOW 4）は**直さず報告のみ**という局長判断に
従っています。重い順に3件だけ挙げると、セッションを失効させる手段が無い／
プロジェクトを1つ作れば全ユーザーのメールを列挙できる／`SKIP_ENV_VALIDATION` が
`JWT_SECRET` の長さ検証ごと外す、です。

なお `as any` / `@ts-ignore` / 空 `catch` / `console.log` / `$queryRawUnsafe` は
本番経路に **0件** でした。素性は良いほうです。
