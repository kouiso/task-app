# 紙面の崩れを見る検査 — `check_page_layout.py`

対象: `scripts/pdf-book/check_page_layout.py`（541行）
退行テスト: `scripts/pdf-book/test_check_page_layout.py`（338行）
登録先: `Makefile` の `book-pdf-test` と `book-pdf-verify`

## なぜ入れたか

`check_pdf_book.py` は本文を**文字列として**取り出して見ている。文字が「出ているか」は
分かるが、「どこに出ているか」は見ていない。だから紙面が崩れても緑のまま通る。

実際に day26 でこれが起きていた。5列表の5列目が幅 4.5mm に潰れ、版面の右外へ 7.2mm
はみ出し、1行のセルが1ページを丸ごと食っていた。文字は全部出ているので、既存の検査は
`✅ 2冊すべて商品として出せる状態です` と言い続ける。

原因は `material/style/book.css` の列幅指定。

```css
th:nth-child(1) { width: 20%; }
th:nth-child(2) { width: 21%; }
th:nth-child(3) { width: 25%; }
th:nth-child(4) { width: 34%; }
```

合計がちょうど 100% なので、`table-layout: fixed` の表で**5列目に残りが回らない**。
CSS のコメントは「列数が4と違う表では指定分が按分されるだけで破綻しない」と書いてあるが、
按分されるのは列数が**少ない**とき（3列表101件は無事）で、**多い**ときは潰れる。
5列表は day12 / day26 / day27 / day28 / day29 の5件ある。

## 何を検査するか

| 検査 | 見るもの | 道具 |
|---|---|---|
| 版面からのはみ出し（墨） | ページを描画して、余白へ出た墨の位置 | `pdftoppm -gray` |
| 版面からのはみ出し（文字） | 行の座標。はみ出した字を引用できる | `pdftotext -bbox-layout` |
| 要素の重なり | 別ブロックの行同士が面積の半分以上重なる | `pdftotext -bbox-layout` |
| 表の列の潰れ | 1文字だけの行が行送りの間隔で縦に積まれる | `pdftotext -bbox-layout` |
| 写真の大きさ・粗さ・縦横比 | 実効 ppi と、そこから逆算した紙面での寸法 | `pdfimages -list` |
| 端切れ | 1〜3文字だけの行の割合 | `pdftotext -bbox-layout` |

依存は poppler だけ。Pillow も numpy も入れていない。`pdftoppm` の PGM(P5) は素の bytes
なので標準ライブラリで読める。明るさの判定は `bytes.translate` + `find` / `rfind` に
落として C 側で回している（1冊 62 ページで 0.1 秒）。

指摘は必ず**人が見に行ける形**で出す。

```
day26_....pdf: p8: 列が幅 4.5mm に潰れ、21行が1文字ずつ縦に積まれている（x=190.7mm, y=41.6〜228.5mm）
day26_....pdf: p14: 文字が版面の右へ最大 12.1mm はみ出す（18行）。いちばん出ているのは y=67.5mm の「npm」
```

## 版面の矩形をどう決めたか（両方やった）

**1. CSS から導いた。** 用紙は A4（210×297mm）。余白は `@vivliostyle/theme-techbook` が
天地 25mm・左右 22mm を指定している（`--vs-page--margin-top` / `-bottom` = 25mm、
`--vs-page--margin-inner` / `-outer` = 22mm）。`book.css` のコメントも版面を
「166mm × 247mm」として同じ値を記録している。よって **版面 = x∈[22,188]mm, y∈[25,272]mm**。

**2. 組んだPDFで実測して裏を取った。** day01 を 72dpi で描画したときの墨の位置は

| 実測 | 値 |
|---|---|
| 左端 | 21.9mm |
| 右端 | 188.0mm |
| 本文の先頭 | 25.4mm |
| 柱の帯 | 10.2〜14.5mm |
| ノンブルの帯 | 282.2〜286.1mm |

1 の値と一致した。

CSS の値だけを信じると、テーマが余白を変えたときに検査が黙って嘘をつく。実測だけで決めると、
はみ出しているPDFを「これが版面や」と学習してしまう。だから CSS を正とし、実測は一致の確認に使う。

柱とノンブルは版面の外（余白のマージンボックス）に正しく置かれる。ここをはみ出しとして
数えると全ページが赤くなるので帯として除外した。除外するのは **天 0〜20mm と地 278〜297mm**
だけで、その内側（20〜24mm・273〜278mm）に墨が来たら本文が余白へあふれたと判定する。
実測の空き（14.5〜25.4mm・272〜282.2mm）より狭く取っているので、正常なPDFは掛からない。

許容は `EDGE_TOLERANCE_MM = 1.0`。版面の縁ちょうどに置かれた表の地色が、罫線の縁と
描画のアンチエイリアスで 0.3mm ほど外へ出る（実測 188.0mm ＝版面の縁ちょうど）ため。

## 判定の境界と、その根拠

| 定数 | 値 | 根拠 |
|---|---|---|
| `RENDER_DPI` | 72 | 1px = 1pt = PDF の座標そのもの。画素と座標の対応を計算で歪めない |
| `INK_LEVEL` | 230 | 引用の地色 `#f6f8fa`・インラインコードの `#eef1f4` は 240 前後。これを墨に数えると全ページが赤くなる |
| `EDGE_TOLERANCE_MM` | 1.0 | 上記。実測のはみ出しは 4.7〜12.1mm なので、見逃す側には倒れない |
| `COLLAPSED_MIN_STACK` | 8 | day26 の潰れた列は 14〜21行。1文字の値が入った普通の列（day26 p31 のステップ番号）は 5行 |
| `COLLAPSED_MAX_PITCH_MM` | 12.0 | 行送りは 12.75pt × 2.05 ≒ 9.2mm。表の行が変わる間隔は実測 16〜21mm |
| `COLLAPSED_WIDTH_MM` | 8.0 | 潰れた列は 4.5mm。いちばん狭い正常な列（20%）は 33mm |
| `MIN_IMAGE_WIDTH_MM` | 130.0 | 修正前は横長 110〜120mm・縦長 24〜33mm（`book.css` の記録）。今の実測は最小 152.4mm |
| `MIN_IMAGE_PPI` | 120 | 1440px を版面幅いっぱいに置くと 220ppi。実測は 213〜240ppi |
| `MAX_PPI_SKEW` | 0.02 | `object-fit: contain` が外れて引き伸ばされたら縦横の実効解像度がずれる |
| `ORPHAN_RATE_LIMIT` | 0.15 | **後述** |

## 端切れの率だけは、まだ実測が2冊ぶんしかない

端切れの定義は `book.css` の記録に合わせて「**1〜3文字だけの行**」。折り返しの結果か
元から短いセルかは区別していない。区別すると数え方が変わって過去の実測と比べられなくなる
（`book.css` は「1〜3文字の行として数えると 241→241 で完全に不変」と、定義を絞ると
嘘になる例まで書き残している）。柱とノンブルは版面の外なので数えていない。数に入れると
全ページが1件ずつ端切れになる。

実測は2冊。

| 冊 | 端切れ / 版面内の行 | 率 | 見た目 |
|---|---|---|---|
| day01 | 129 / 1547 | 8.3% | 窮屈だが読める（p6 で「エス」「クス」「文」「ける」が単独行） |
| day26 | 230 / 1094 | 21.0% | 5列表が潰れて崩壊 |

`0.15` はその間に置いた。**36冊を組んだら実測で見直すこと。** 2冊では母集団が足りない。
上げるにせよ下げるにせよ、日ごとの率を並べてから決めるべきで、今の値は暫定。

## 画像の紙面寸法は `pdftoppm` ではなく `pdfimages` から出している（指示との差分）

依頼は「`pdfimages -list` で実効 ppi、`pdftoppm` の描画で紙面上の占有面積を取る」やった。
実効 ppi は指示どおり `pdfimages -list` から取っているが、**紙面での寸法はそこから逆算**
している（画素数 ÷ ppi = インチ）。理由は、描画した絵から写真の輪郭を拾うと表の地色や
mermaid の図と見分けがつかず、当て推量になるため。ppi は poppler がラスタライズに使う
数そのものなので、逆算した寸法は近似ではなく正確な値になる。

`pdftoppm` の描画は、版面からのはみ出し（写真が紙の端へ出ていないか、を含む）に使っている。

## 実行

```bash
make book-pdf-test     # 退行テストだけ（PDF も poppler も不要）
make book-pdf-verify   # book-pdf-test → check_pdf_book.py → check_page_layout.py
python3 scripts/pdf-book/check_page_layout.py [PDFのディレクトリ]   # 既定 dist/pdf
```

`|| true` も空 catch も入れていない。poppler が1本でも無ければ `check_pdf_book.py` と同じく
exit 2。PGM が読めない・`pdfimages` の表が読めない・行の座標が1件も取れないときは
`ToolFailure` を投げて問題一覧に載せる。空の結果を返して「問題なし」に化けるのがいちばん
たちが悪いため。

## 退行テストが何を守るか

52ケース。PDF も poppler も要らない（`test_check_pdf_book.py` と同じ）。

判定境界が本当に固定できているかは、定数を1つずつ壊して確かめた。
**14個すべてで、対応するケースが落ちる。**

```

COLLAPSED_MIN_STACK 8→5          ❌   MIN_IMAGE_PPI 120→90            ❌
```

外部出力の読み取りも固定してある。`pdfimages -list` は `object ID` だけが見出し2語・値2語で
真ん中の列数が見出しと合わないため、前後の両端から数えている。`pdftotext -bbox-layout` の
xhtml は poppler の版で名前空間が付いたり付かなかったりするので、根の tag から実際の接頭辞を
取って使っている（決め打ちすると片方で1行も取れず、検査全体が「問題なし」で通る）。
