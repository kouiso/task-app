## 今回のスコープ外として記録するもの

次の2件は壊れているわけではないが、通して読むと気になる点として残す。直すかどうかは
別の判断になるため、この監査では変更していない。

1. **ロードマップへの導線が2箇所しかなかった（対応済み）**
   `00-1_学びのロードマップ.md` へのリンクは `00_カリキュラム目次.md` と day01 にしかなかった。

   すべてのdayが「明日のプレビュー」または「次回予告」で締めくくられていたが、次のファイルへの
   リンクが無く、読者は次に開くファイルを自分で探すことになっていた。

   30日分の末尾に「次に読むもの」の節を足した。前の日、次の日、学びのロードマップ、目次への
   4本のリンクを置いている。追加後に相対リンクの解決を確認し、切れているものは1件も無い。

3. **どこからも参照されていない画像が16枚あった（削除済み）**
   `screenshots/` にある71枚のうち16枚が、36ファイルのどこからも参照されていない。
   販売ZIPには入るため、読まれないまま容量だけを占める。

   このうち4枚は、写っている画面が説明と違うことが分かって参照を外したものである。
   撮り直しが要る。

   `day02-` で始まるものが4枚、`day03-` が2枚、`day04-` が3枚、`day08-` が2枚である。

### 自分の修正が壊した箇所

一括置換で `（同じファイルの続き）` が最大6回積み上がった（day01 の5箇所、day14 の2箇所）。
原因は、書き換え済みのバッファから値を拾い直したこと。検査 `check_anchor.py` に
「同じ注記が2回以上ぶら下がった値」を止める規則を足して塞いだ。

day30 の Vercel コマンドを直す際、`npx dotenv` を使う形に書き換えたが、読者の環境に
入るのは `dotenv`（ライブラリ本体）で実行ファイルを持たない。追加の道具を要らない
`set -a` と `.` の形へ再修正し、値が渡ることを実際に実行して確認した。

day25 のパスワード復旧手順も、書きかけの段階で誤りに気付いて訂正した。
`npm run db:seed` は既存ユーザーを書き換えない（`scripts/_seed/seed.ts:58` の `update: {}`）。
