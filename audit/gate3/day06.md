### 1. 行493 定義順の指示が、直前の宣言とも完成コードとも食い違う

**逐語引用**

```
`RegisterPage()` の中で、Step 3 で書いた `useForm` の設定の**前**（関数の先頭）に以下を追加します。
```

**何ができないか**

直前の行489が「最終的な定義順は `router` → `error state` → `useForm` → `registerMutation` になります」と
宣言しているのに、行493の指示どおり貼ると `registerMutation` が `useForm` の前に来る。
どちらが正しいのかを決められず、完成コードと自分のファイルを見比べても一致しないまま止まる。

**教材のどこが足りないか**

行493が指す貼り付けブロック（行495から515）は `router`、`error state`、`registerMutation` の3つを
まとめて含み、それを `useForm` の前に置かせている。一方、完成コード（行962から991）では
`registerMutation` が `useForm` の後ろにある。指示、宣言、完成コードの3つが食い違ったままで、
「後で移す」といった訂正の指示がどこにもない。

**反証側が確かめた根拠**

- 行489の宣言、行493の指示、行495から515のコードブロック、行962から991の完成コードを現物で照合した。
- 行974の理由づけは `router` と `setError` を先に置く話であって、`registerMutation` の位置を決めていない。
- `registerMutation` の全出現（489/503/517/535/547/560/664/665/671/862/974/979/996/1121/1122）と
  「定義順・順番・順序・並び」の全出現（489/533/895/974/1141）を検索したが、訂正指示は存在しない。
- 同一ファイル内の矛盾なので、前の日や配布済みの足場では埋まらない。
- 順序を変えてもコンパイルは通るため、読者は実行結果から正解を判定できない。
  行1004が完成コードとの突き合わせを促しているので、一致しない状態で止まる。

### 2. 行714 まだ紹介されていないアカウントでログインさせている

**逐語引用**

```
Day 07 からは `admin@example.com` でログインし直して進めます。ブラウザのアドレス欄に `http://localhost:3000/login` と直接入力し、`admin@example.com` / `password123` でログインしてください。
```

**何ができないか**

自分で作った覚えのないアカウントでログインしろと言われ、そんなアカウントは存在しないと考えて手が止まる。
ログインが通らなかった場合に、パスワードの写し間違いなのか、そのアカウントが無いのかを切り分けられない。

**教材のどこが足りないか**

このアカウントは Day 01 の初期セットアップが投入するシードデータ由来だが、Day 01 のログは
「シードデータを投入しています...」の1行だけで、どんなアカウントが作られたかを書いていない。
同じ文にある「初期データのプロジェクト」も初出で説明がない。

**反証側が確かめた根拠**

- 行714の文言を現物で確認した。
- Day 01 の行315のログ表示と前後（行260から330）を通読したが、作られるユーザーの一覧は無い。
- Day 02 から Day 05 と付録を横断検索した結果、`admin@example.com` は Day 05 の行926から927と
  行999から1000の2箇所だけで、いずれも「読み比べ用、ここは写経しません」と明記されたサンプル内の
  バリデーション入力例。実在するアカウントだという説明は無い。
- Day 06 内の他の出現（行743、行809）は重複チェックの例で、シード由来の説明ではない。
- シード情報の表が初めて出るのは Day 07 の行1352から1360。Day 06 時点では読者に知る手段が無い。
- 再投入コマンド `npm run db:seed` の記載も付録にあるだけで、Day 06 本文から案内されていない。
