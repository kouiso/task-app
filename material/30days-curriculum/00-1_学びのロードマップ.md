# 学びのロードマップ（30日カリキュラム全体像）

このカリキュラムでは30日かけて1本のタスク管理アプリを「動かす → 公開する → 機能を積む → 仕上げて公開する」順で育てます。各日は前の日に書いたコードを使います。Day 01から順番に進めてください。

各日の教材は[カリキュラム目次](00_カリキュラム目次.md)から開けます。詳しい操作手順は各日の教材を見てください。学ぶ順番と各技術を使う日を、このロードマップで確認できます。

## 8つの局面

30日は8つの局面に分かれます。局面の区切りは[カリキュラム目次](00_カリキュラム目次.md)の Phase と同じです。各局面の終了時点で作る機能を示します。

| 局面 | 日 | テーマ | 終わったときにできること |
|------|-----|--------|------------------------|
| 1. 環境構築・即公開 | Day 01-04 | 環境構築 → ダッシュボード → Git → Vercel公開 | 自分のアプリをインターネットのURLで開ける |
| 2. ログイン機能 | Day 05-08 | ログイン・登録フォーム → 認証バックエンド → 共通レイアウト | ログイン機能と全ページ共通のサイドバーを作る |
| 3. プロジェクト管理 | Day 09-12 | 一覧 → 新規作成 → 編集・削除 → メンバー | プロジェクトの作成・編集・削除とメンバー追加を行う |
| 4. タスク管理 | Day 13-17 | 一覧 → 作成 → 編集・削除 → ステータス・作業時間記録 → マイタスク | タスクの基本操作一式と作業時間の記録ができる |
| 5. コメント・検索 | Day 18-20 | コメント → コメント編集 → 検索 | コメントとタスク検索を使う |
| 6. ダッシュボード・レポート | Day 21-23 | 統計 → グラフ → 週次レポート | データの集計とグラフ表示ができる |
| 7. ユーザー管理 | Day 24-25 | ユーザー一覧 → プロフィール編集 | 管理者機能とプロフィール編集を作る |
| 8. 仕上げ・完成公開 | Day 26-30 | エラー対応 → 詳細画面 → 一括操作 → ユーザー詳細 → 本番公開 | バグへの対処と機能の追加を終えて完成版を公開する |

## 技術のつながり（習う日と再び使う日）

このカリキュラムでは同じ書き方を複数の機能で使います。最初に習う日と応用する日を並べました。前の日のコードで分からない箇所があれば該当する教材へ戻って確認してください。

| 技術の型 | 最初に習う日 | 応用・復習する日 |
|---------|-------------|------------------|
| react-hook-form + zod（フォーム） | Day 05 | Day 06・10・14・18・25・29 |
| ダイアログ（モーダルのフォーム） | Day 10 | Day 11・14・15・16 |
| tRPC useQuery（データ取得） | Day 08-09 | Day 13・17・20・21 ほか取得のある画面すべて |
| tRPC useMutation（作成・更新・削除） | Day 05 | Day 06・08・10・11・12・14・15・16・18・19・25・28・29 |
| tRPC手続きの自作（入力・処理・戻り値の3部品） | Day 07（認証API） | Day 09（getAll）以降のサーバー側すべて |
| キャッシュの無効化（invalidate） | Day 10 | Day 11・12・14・15・16・18・19・25・28・29 |
| 権限チェック（本人・管理者の切り分け） | Day 07・12 | Day 19・24・29 |
| Recharts（グラフ） | Day 22 | Day 23 |

## 大きな2つの周回

このアプリの中心は「プロジェクト」と「タスク」です。この2つはほぼ同じ CRUD（作成・取得・更新・削除）の流れを別々にたどります。

- プロジェクトの周回: Day 09（取得） → Day 10（作成） → Day 11（更新・削除） → Day 12（メンバー）
- タスクの周回: Day 13（取得） → Day 14（作成） → Day 15（更新・削除） → Day 16（ステータス・作業時間記録）

プロジェクト側で使った書き方をタスク側でも使います。2周目ではフォームの項目やAPIの処理対象を変えます。分からなくなったら1周目のプロジェクト側と見比べてください。

## 進め方のコツ

各日の冒頭にある「今日のゴール」を先に読みましょう。完成時の画面や操作を確認してから手を動かします。

コードを写したあとはその下の「なぜこう動くか」を読みましょう。処理の理由を確認して次の日の実装に使います。

つまずいたらその日の「つまずきポイント」の表を見ましょう。該当する症状と対処方法を確認します。
